Aligning the CI coverage decision with the rest of the app

Eleven differences between this screen and the two it sits next to — the work queue and the case detail page. Every value below is measured off the running app, both sides. None of the changes touches information, functionality or the order anything appears in: each one swaps a bespoke treatment for the app component that already does that job.

2 · The chip — the single biggest tell

Every status on this page is a rimmed, neutral-ink pill. Every status everywhere else in the app is a rimless, tinted, status-coloured one. Side by side at the same size:

now — ToneChip, rim + neutral ink
Action required Resolution decision Strategic

The rim is what reads as foreign: it makes each chip an outlined object, and the ink carries no meaning, so tone lives only in a 10%-opacity wash and a 30% border.

proposed — the app's Badge
Action required Resolution decision Strategic

No rim, a 15% wash, and the ink takes the tone — so the status is legible from the colour of the word, which is how every other screen signals it.

One file, and this is why it is first. Pill in coverage/primitives.tsx is already a thin alias over ToneChip, so repointing it at Badge moves every status on the page at once. The catch, stated: that file moved AWAY from Badge on purpose, because the findings group had grown bordered chips and the page then spoke two chip languages. So the findings verdict and the two cause markers have to move in the same change — otherwise this swap just relocates the inconsistency instead of removing it.

5 · Deliberately not in this change

  • The page toolbar. Both reference screens carry Refresh and Ask AI top-right; this page has neither. Adding them is new functionality, which is outside the brief — named here so the remaining gap is known rather than forgotten.
  • The centred reading column. The case page is full-width with a right rail; this is a 1180px centred column. Going full-width would restructure the layout rather than restyle it. The gutters move to PageContainer's 16/24/32; the column stays.
  • Section order, wording, folds and controls. Untouched, all of it.
  • The evidence, resolution and manifest internals. Already the app's components after the last change; nothing here re-opens them.

Everything above is a token or a component swap. No reducer, no store, no props that carry data — which is what makes it safe to do in one pass and easy to revert in pieces.
